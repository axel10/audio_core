## Android USB 独占（bit-perfect）方案调研

结论：三条路线，工作量差一个量级。

- **A. 官方 AudioMixerAttributes BIT_PERFECT（Android 14 / API 34+）**
  - API：`AudioManager.getSupportedMixerAttributes(device)` / `setPreferredMixerAttributes(attrs, device, mixerAttrs)` /
    `clearPreferredMixerAttributes` / `addOnPreferredMixerAttributesChangedListener`
  - `AudioMixerAttributes.Builder(format).setMixerBehavior(MIXER_BEHAVIOR_BIT_PERFECT)`
  - 仅限 USB 设备 + `USAGE_MEDIA`；`AudioFormat` 的 encoding/channelMask/sampleRate 三项必须与 mixer attrs 完全一致才会挂上
  - 厂商侧是**选配**：需要 `AUDIO_OUTPUT_FLAG_BIT_PERFECT` + AIDL HAL + `usb_audio_policy_configuration.xml` 动态 mix port
  - 不需要 USB 权限；bit-perfect 时框架无软件音量，音量由 DAC 硬件控制
  - 回调里 mixerAttributes 变 null = 被系统降级
- **B. 自带 UAC 驱动（UAPP / FiiO / HiBy 路线）**
  - `UsbManager.openDevice().getFileDescriptor()` + `libusb_wrap_sys_device()`（`LIBUSB_OPTION_NO_DEVICE_DISCOVERY`）
  - 自己解析 UAC1/2 描述符、claim streaming interface、isochronous URB、feedback 端点时钟同步
  - 可以 native DSD，不依赖厂商 HAL；但机型/内核/SELinux 兼容性风险大
- **C. AAudio EXCLUSIVE / MMAP_NOIRQ**：只解决延迟和 mixer 绕过，不保证 bit-perfect（HAL 仍可能 SRC/音量），USB 上 MMAP 通常拿不到。不作为方案。

## 路线 B（自研 UAC 驱动）可借鉴的开源实现

- **Flick（github.com/moss-apps/Flick，MIT）** —— 技术栈与本项目几乎一致：Flutter + Rust +
  flutter_rust_bridge + rusb + cpal/Oboe。`rust/src/uac2/` 实测 **18,897 行**（含约 1.1k 行测试），
  其中 `android_direct.rs` 单文件 **8,916 行**。含 descriptor 解析、iso 传输、DAC/DSD quirk 表、
  错误恢复、fallback。其 `audio/strategy.rs` 有后端打分：DapNative 100 / MixerBitPerfect 80 /
  UsbDirect 70 / MixerMatched 60 / ResampledFallback 10。
  关键：**rusb 不暴露 isochronous API**，它直接 `use libusb1_sys` 调
  `libusb_alloc_transfer` / `libusb_fill_iso_transfer` / `libusb_submit_transfer`。
- **yuHIFI（github.com/jasyu666/yuHIFI，PolyForm Noncommercial，不可商用）** —— Kotlin + C++/NDK，
  `UacParser.kt` + `iso_player.cpp`。README 的实战约束极有价值（见下）。
- **SpotiFLAC-Mobile** —— Rust + libusb1-sys + uniffi，`descriptors.rs` / `transport.rs`，fail-closed 策略。
- **esp-uac2-host / arduino-audio-tools USBAudioHostBase** —— 嵌入式 UAC2 host，协议层（feedback
  16.16/10.14、clock topology、alt setting 选择）可读性好，不适合直接移植。
- **Linux kernel `sound/usb/`** —— quirk 表与描述符解析的权威参考。

## 自研 UAC 的硬坑（来自上述项目实战记录）

1. 包长必须按**样本数**做 Bresenham 小数分配，不能按字节对齐帧边界 —— 否则 44.1kHz 实际跑成 40kHz。
2. USB 提交线程内禁止文件 I/O 与内存重分配（会卡死，且卡顿周期精确翻倍：4.1/8.3/16.6s）。
3. libusb 所有裸指针必须属于同一线程；回调里只能置标志，不能调 stop()（自我 join）。
4. **不信任设备自报能力**：部分 DAC 对任何采样率都回 `SET_CUR` 成功，实际只支持固定几档，能力表需实测。
5. 直连时需请求 `AUDIOFOCUS_GAIN`，否则被系统抢占。
6. 很多 DAC 无 Feature Unit 硬件音量 → 需自实现软件音量（yuHIFI 方案：24bit 左对齐到 32bit，
   衰减消耗低 8 位空位，−48dB 内不丢有效位）。
7. libusb 为 LGPL-2.1，静态链接需满足可重链接义务。

## Flick uac2 可搬性结论（实测依赖分析）

- 外部耦合极低：`descriptors/`、`transfer*`、`iso_packet_*`、`ring_buffer`、`control_requests`、
  `capabilities`、`endpoint`、`stream_config`、`format_negotiation`、`compatibility`、`quirk`、
  `error*`、`fallback_handler`、`volume_control` **只依赖 rusb / libusb1_sys / log / serde /
  parking_lot / once_cell / crossbeam**，可整块搬。
- 只有 `audio_sink.rs`(206 行) 与 `backend.rs`(119 行) 依赖 Flick 自己的 `crate::audio`
  （`SourceProvider` / `AudioBackend`）→ 这两个是接插件，直接丢掉自己写。
- `android_direct.rs`(8916 行) 仅 6 处 `crate::audio::*`：thread priority、DSD override、
  XRUN 计数 → 全部可桩掉。
- Cargo 依赖是标准 crates.io：`rusb 0.9` + `libusb1-sys 0.7`（默认 vendored），靠 cargokit +
  NDK clang 编译，三架构需实测。
- 风险：Flick `mod.rs` 有 `#![allow(dead_code)]` + "feature in progress, not all public API is
  wired yet"；docs 称 UAC2 路由 "shifted to Android's native USB DAC handling"，说明这套在
  Flick 内已非主力路径，接手后维护自负。

## 移植的三大粘合点（搬不走的部分）

1. **PCM 进 Rust**：Android 解码在 Kotlin（media3 + ffmpeg extension），需自写 `AudioSink`
   转发层把 PCM 经 JNI 送 Rust（推荐），或把解码整体搬进 Rust（等于换引擎）。
   注意 media3 `DefaultAudioSink` 是 final，不能继承，只能实现 `AudioSink` 接口或包一层。
2. **FD 传递**：Flick 放在 MainActivity，audio_core 是 plugin，需挪到 plugin 的 Kotlin 类，
   不依赖 Activity 生命周期。
3. **libusb 交叉编译**：vendored + cargokit，需验证 arm64-v8a / armeabi-v7a / x86_64。

## 项目现状（改造缺口）

- Android 播放链路：`MyExoplayerPlugin.kt` → ExoPlayer + `DefaultAudioSink`（`buildAudioSink` 里挂了
  `CppEqualizerProcessor` + `FFTAudioProcessor`）→ AudioTrack → AudioFlinger，默认 48k 混音，非 bit-perfect
- 另有 `ensureAudioEffects()` 挂 `android.media.audiofx.Equalizer/BassBoost`，同样破坏 bit-perfect
- 已核实：media3 1.9.3 全部 aar 中**没有** `AudioMixerAttributes` 相关符号 → 官方路线要在应用层自己调 AudioManager，
  并保证 DefaultAudioSink 产出的 AudioFormat 与 mixer attrs 一致
- Rust 侧 Android target 只有 jni / android_logger / ndk-context，无 cpal / 音频输出，音频输出全在 Kotlin
